# 快速开始（临时移出内容）

> 临时文档，暂不发布到网站。

## OBS：融合器光标（直播叠加）

想在直播/录屏画面里显示鼠标光标，可以不用任何 app：「参数配置 → 光标显示方式」选
**融合器光标**，然后在 OBS 里：

1. 添加**浏览器源**，地址填 `http://192.168.73.1/#cursor`（与设备同一局域网的电脑均可打开）
2. 把浏览器源拖到游戏采集画面之上、调整到与游戏画面重合
3. 需要抠像时给该源加**色键（Chroma Key）滤镜**，并在页面里点击屏幕把背景调成绿色
   （页面默认黑色；也可以用 `?color=十六进制` 直接指定背景色）
4. 页面打开时自动按**当前配置的分辨率**划一块固定比例的虚拟屏幕，光标只落在其中——
   游戏画面只占采集画面一部分时，把虚拟屏幕与游戏画面对齐即可；点击屏幕弹出的控件里
   会显示虚线框与当前分辨率，方便对位

> 指针位置与触屏落点同坐标系（外接显示器的黑边缩放已含在内），页面任意分辨率自适应；
> 光标隐藏（如关闭映射）时页面只剩纯背景，色键后即完全透明。

## 添加到主屏幕（可选）

配置面板可以安装到手机 / 平板主屏，之后像 App 一样全屏打开（没有浏览器地址栏，也没有标签页）：

- **苹果（Safari）** — 打开 `http://192.168.73.1/` → 分享 → 「添加到主屏幕」
- **安卓（Chrome）** — 用 vPointer 转发后的 `http://127.0.0.1:8000` 打开面板 → 右上菜单 → 「安装应用 / 添加到主屏幕」

> 浏览器只把 `http://127.0.0.1` 和 `https://` 当作「安全来源」。安卓直接打开 `http://192.168.73.1` 时只会生成普通快捷方式（点击后仍在浏览器标签页里打开）；iOS 不受此限制。

安卓端安装后仍需 vPointer 保持运行；苹果端只要 Pico 保持连接。面板不会离线缓存，它显示的永远是设备上的当前状态；首次安装需要联网获取图标。

## touch_forwarder 触屏转发

`touch_forwarder` 运行在安卓手机上，可实现手搓与开发板共同工作不冲突

### 安装

adb 连接PC后，在PC的终端执行：

```sh
curl.exe -fL --retry 3 -o touch_forwarder_arm64 "https://1833788059.cdn.123clouddisk.com/1833788059/direct/projects/touch_forwarder/touch_forwarder_arm64"
adb push touch_forwarder_arm64 /data/local/tmp/touch_forwarder_arm64
adb shell chmod 755 /data/local/tmp/touch_forwarder_arm64
```

### 测试运行

```sh
adb shell /data/local/tmp/touch_forwarder_arm64
```

看到「监听 :6532，等待客户端…」即工作正常，此时插入开发板即可手搓不冲突。

### 后台运行

测试正常后，按 `Ctrl+C` 退出，使用如下命令进入后台运行，之后PC可断开，保持usb调试开启即可：

```sh
adb shell /data/local/tmp/touch_forwarder_arm64 start
```

- 程序脱离终端持续运行：关掉 cmd 窗口、拔掉 USB 线都不影响
- 只有 `stop`、手机重启或系统强杀会让它停下；手机重启后重新执行一次 `start` 即可

### 管理命令

```sh
adb shell /data/local/tmp/touch_forwarder_arm64 status    # 运行状态：pid、已运行时长、日志大小
adb shell /data/local/tmp/touch_forwarder_arm64 logf      # 实时查看日志（Ctrl+C 只退出查看）
adb shell /data/local/tmp/touch_forwarder_arm64 log 200   # 最近 200 行（默认 50 行）
adb shell /data/local/tmp/touch_forwarder_arm64 restart   # 重启
adb shell /data/local/tmp/touch_forwarder_arm64 stop      # 停止
```


## 状态指示灯

板载 RGB LED 指示设备状态（亮度由固件 `FR_DEBUG_LED_BRIGHT` 配置）：

| 阶段 | 颜色 | 含义 |
|------|------|------|
| 开机 | 洋红 | 正在检测恢复出厂 strap |
| 开机 | 红 | 未检测到恢复出厂 strap（正常） |
| 开机 | 绿 | 检测到 strap，正在擦除配置 |
| 开机 | 蓝 | 配置擦除完成 |
| 运行 | 绿 | 已连接主机设备 |
| 运行 | 熄灭 | 未连接主机设备 |

> 恢复出厂 strap：上电时短接 GPIO29 与 3V3。

## 故障恢复

### 固件启动失败自动进入 BOOTSEL

固件内置自恢复机制：若固件**连续 2 次启动失败**（每次上电 8 秒内未完成初始化，例如刷入了损坏或不兼容的固件文件），设备会自动重启 1~2 次后进入 **BOOTSEL 模式**——电脑/主机上会出现名为 **RP2350** 的 U 盘。

恢复方法：从发布页下载正确的 `.uf2` 固件文件，**拖入 RP2350 U 盘**（或用 picotool 刷入），设备自动重启回正常固件。全程无需拆机、无需按 BOOTSEL 按键。

> 此机制针对**固件本身**的启动失败；配置数据损坏请用下文的「恢复出厂设置」。

### 恢复出厂设置

如果配置异常导致设备无法正常启动，或想清空所有设置回到出厂默认，可通过以下任一方式恢复出厂设置：

| 方式 | 操作 | 适用场景 |
|------|----------|----------|
| **配置面板** | PICO 配置 → 危险操作 → 恢复出厂设置 | 设备能正常启动、能访问配置面板 |
| **GPIO strap** | 上电时短接 **GPIO29 与 3V3**，再连接电源供电 | 设备无法启动 / 无法访问配置面板 |

> ⚠️ **恢复出厂设置会清除全部数据**，包括所有按键映射、屏幕方向、手柄/轮盘参数与 Lua 脚本，设备重启回到出厂默认，且不可撤销。

## root 设备：插网卡后整机断网

**现象**：root 过的平板/手机插上 USB 网卡后整机断网，WiFi 已连接却不被使用，也不弹"登录到网络"提示；拔掉网卡即恢复。

**原因**：设备上的 root 广告拦截/代理类模块（内置 Clash 的去广告模块、AdGuard、加速器等）劫持了全机 DNS 和流量，替 USB 网卡"完成"了系统的联网检测，使其被误判为可上网并获得最高优先级；而实际它没有外网，拦截模块的上游又绑定了这块网卡，形成死循环导致断网。此问题与固件无关，未 root 设备不受影响。

**解决**（任选其一）：

1. 使用 USB 网卡期间停用该模块（Magisk 模块开关或 `killall clash`），拔插一次网卡即可恢复；
2. 需要常驻：关闭模块的 `fake-ip` DNS 模式，并将 `192.168.73.0/24` 加入 DIRECT 绕行名单；
3. 自查：root shell 执行 `ps -A | grep -iE "clash|adguard|proxy"`，有输出即中招。
